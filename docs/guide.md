# 使用指南：从 0 到"知识库 + 订阅"跑起来

这份文档回答"**我该往哪儿写、写完会发生什么、出问题看哪里**"。
规范本身在 [../SPEC.md](../SPEC.md)，订阅的完整契约在
[subscription-protocol.md](subscription-protocol.md)；本文件是操作手册。

---

## 1. 五分钟上手

```bash
# ① 变成你自己的仓库
git clone git@github.com:<you>/ai-creator-knowledge.git my-knowledge
cd my-knowledge

# ② 先改画像——它是所有写作约束的来源
$EDITOR profile/账号画像.md

# ③ 声明你关注的订阅源（一个源一个文件）
cp feeds/_template.md feeds/晚点.md   # 然后填 title / url / group / weight + 策展理由

# ④ 加一条自己的经验（标题就是结论）
$EDITOR "learnings/钩子/前3秒说处境比说收益更留人.md"

# ⑤ push
git add -A && git commit -m "init my knowledge base" && git push
```

然后到桌面：**设置 → 内容知识库 → 同步源配置 → 新增源**
（name 随便，例如 `my-knowledge`；url 填你的仓库地址）→ **Sync**。

一次 Sync 之后你会得到：

| 你写的 | 桌面上变成 |
|---|---|
| `skills/<name>/SKILL.md` | 一个可调用的 agent 技能（对话里直接生效） |
| `templates/<name>/SKILL.md` | 同上 |
| `learnings/` `assets/` `docs/` `profile/` 里的 `.md` | 可被 `knowledge__recall` 检索的条目 |
| `feeds/*.md` | 灵感面板里真实的订阅（分组、排序、备注都在） |

## 2. 每一类怎么写

### 2.1 `learnings/` —— 一条可复用的结论

标题写结论本身，正文四段。最小可用示例：

```markdown
---
title: 前 3 秒说处境，比说收益更留人
summary: 同一选题的两种开头，前者是描述读者当下，后者是承诺还看不见的好处
tags: [钩子, 完播率]
domain: [短视频]
date: 2026-09-11
author: 我
confidence: 0.6
sources: [https://…]        # 外部事实必须能点回去；自己的判断标「口述」
---

## 结论
## 证据
## 怎么用
## 反例 / 边界     ← 写清什么条件下不成立，否则会被当成万能药复用
```

### 2.2 `assets/选题库/` —— 选题卡

四件事必须齐：**给谁、为什么现在做、角度、需要什么素材**。缺一件说明还没想清楚。
frontmatter 加 `status: develop|scheduled|published`。

### 2.3 `docs/` —— 方法论与规则

长文、平台规则、SOP。平台规则类的内容记得在正文里写**查询日期**——规则会变。

### 2.4 `profile/` —— 画像（AI 只读）

账号定位、受众、语言风格、禁区。写进去的每一条都是 AI 写作时的硬约束；
AI 不会替你改这份文件。

### 2.5 `skills/<name>/SKILL.md` —— 让 agent 会做一件事

```markdown
---
name: xhs-note-outline
description: 小红书图文笔记骨架。当用户要把一个选题写成小红书图文、需要封面文案与 6–9 张图的内容分配时使用。
---

# 标题
## 何时用
## 输入
## 步骤
## 输出
## 反例
```

两条硬性要求，做不到技能就不会生效：

1. 目录里**必须有 `SKILL.md`**（没有就整包忽略）；
2. `description` 是 agent 选中它的**唯一**依据——写清"做什么 + 什么时候用"。

> **名字冲突**：技能部署是平铺的（`$DSH_HOME/skills/<name>/`），
> 所以 `<name>` 在整台机器上要唯一。多个仓库给了同名技能时，
> 按内容知识库配置里的源顺序"先到先得"。

### 2.6 `feeds/<slug>.md` —— 声明一条订阅

```markdown
---
title: 晚点 LatePost
url: https://example.com/feed
type: auto          # 或 rss / atom / rdf / json
group: 中文科技      # 分组头（可选）
weight: 10          # 越小越靠前（可选）
tags: [科技, 商业]   # 随源保存（可选）
enabled: true       # false = 停用（可选）
---

为什么订它、要从里面看什么、怎么用——这段会成为这条订阅的备注，
出现在源行悬停提示和阅读器标题下方。
```

写完之后（push + Sync）不需要在灵感面板里做任何事：**订阅链接跟着仓库走**。

## 3. 推送之后，桌面侧到底发生了什么

```
你 push  ──▶  内容知识库 Sync  ──▶  knowledge/feeds.json  ──▶  灵感
               （技能 + 索引）        （归一化后的订阅清单）      （订阅 + 抓文章）
```

**触发点（四个）**

| 时机 | 行为 |
|---|---|
| 你在设置页点 **Sync** | 拉仓库 → 部署技能 → 重建索引 → 出版订阅清单 |
| 面板/对话里调 `knowledge__sync` | 同上 |
| 打开灵感面板 | 静默检查订阅清单（没变就什么都不做） |
| 点灵感的**刷新全部** | 先导入清单（有变化就订阅/更新），再抓文章 |
| 点灵感的**从知识库同步** | 只导入清单；**新增了源就顺手只抓那几个新源** |

**导入时不会动你的东西**（这是设计约束，不是巧合）：

- 你**手动加的源永不被接管**——即使仓库声明了同一个 URL，也只补一个缺失的分组；
- 你在这台机器上改过的标题 / 分组**不会被下一次导入抹掉**；
- 仓库**撤回**一条声明 → 该源标「库已移除」，**文章一条不删**，并且**停止更新**；
- 仓库写 `enabled: false` → 停用：留着文章，任何刷新都不抓；
- **整个知识库被删掉**（源从配置移除、或 `feeds.json` 没了）→ 订阅原样保留，
  从此它们就是"你自己的源"，随时可删。

## 4. 排错 / 常见问题

**Q. 我改了仓库，桌面没反应？**
先看**设置 → 内容知识库 → Sync** 的结果行：它写着 `N source(s): X updated, Y unchanged ·
… · M 订阅源 published for 灵感`。若 `unchanged` 是 1，说明远端 HEAD 没变（没 push 成功，
或推到了别的分支）。

**Q. 订阅没出现 / 少了几条？**
设置页 → 「详情」→ **被跳过的订阅源声明**，每条都会写清原因：`missing url`（忘写地址）、
`not an http(s) url: …`（地址不是 http/https）、`duplicate of <id>`（与另一条重复，
归一化后是同一个地址）。改完 push + Sync 即可。

**Q. 灵感里新订阅是空的？**
点「从知识库同步」时会**自动补抓新增的那几个源**；如果那条源本身抓不到（403、不是订阅源等），
同样会以红色 Toast 报出来，源行右上也会出现红点与原因。另外「刷新全部」也会抓它。

**Q. 某个源我删不掉？**
右键 → 如果显示的是「由知识库管理」，说明**仓库里还声明着它**：删了只会丢掉本地已抓文章，
下次导入又会订阅回来。正确做法是去仓库删掉 `feeds/<slug>.md` 后 Sync，它就会变成
「库已移除」，那时再删。

**Q. 「清理已移除的订阅」什么时候出现？**
只有当存在「仓库撤回、但文章还在」的源时才出现（轨道里的一行，带数量）。
它只清这些，不会碰仓库仍在声明的源，也不会碰"仓库整个消失"后留下来的源。

**Q. 为什么有两条看起来一样的订阅？**
检查它们的 URL 是否真有区别（`?utm_source=…`、末尾斜杠、`http`/`https` 都算同一个地址，
会在归一化后合并）。真正不同的地址就是两条。

**Q. 技能没进对话？**
三查：① 目录里有没有 `SKILL.md`；② 目录名是不是以 `_` 开头（草稿不部署）；
③ 名字是否与本机已有技能冲突（平铺部署，按源顺序先到先得）。
另外技能是**应用启动时**扫描的，装完重启一次再试。

**Q. 检索里混进了不该是内容的条目？**
十有八九是索引目录里的 `README.md` 或说明文件——`learnings/` `assets/` `docs/` `profile/`
下**每个 `.md` 都是条目**（`_` 前缀在这里也不算隐藏）。目录说明请写在根 `README.md` 或
`docs/` 里的正式文档中。

**Q. 面板说"订阅清单读不出来（文件损坏）"或"由更新的版本写出"？**
前者是 `$DSH_HOME/knowledge/feeds.json` 坏了（手动改过、或写到一半）——重新 Sync 一次会重写；
后者是那个文件由更新版本的应用写的（`version` 比本机认的新），升级应用即可。

**Q. 我能只订阅、不建知识库吗？**
可以，但要走内容知识库：仓库里哪怕只放 `feeds/`，也要在**设置 → 内容知识库**里登记它并 Sync，
订阅才会流到灵感。理由是"仓库是唯一事实来源"，灵感不自己扫 git。

**Q. 多个仓库会互相覆盖吗？**
不会。订阅按归一化 URL 合并（先声明的胜），技能按源顺序先到先得，
索引按 scope 分区。你可以在 `config.json` 的 `projects` 里给不同项目配不同的源组合。

## 5. 给团队/多仓库的建议

- **一个仓库一个语义**：别把三个垂类的经验塞进同一个 `learnings/`，用子目录或分仓库；
- **订阅源按仓库归属**：`feeds/` 属于仓库（不是某个人），所以大家 clone 到同一套信息源；
- **改标准要一起改文档**：改 [../SPEC.md](../SPEC.md) 或 `subscription-protocol.md`
  等于改契约，记得同步桌面侧的实现（两边都在 `dsh-desktop` 仓库里）；
- **别提交同步产物**：`$DSH_HOME` 下的索引/缓存不进仓库（见 `.gitignore`）。
